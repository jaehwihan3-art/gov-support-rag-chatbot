# 4단계 평가 결과: 질의응답 평가셋

실행일 2026-11-18 · 평가셋 `data/eval/qa_eval.csv` (30문항) · 실행 `run_qa_eval.py` · 비교 `compare_graders.py`

## 1. 평가셋

| 유형 | 문항 | 정답 기준 |
|---|---|---|
| 답 있음 (A01~A20) | 20 | 질문의 핵심(금액·기간·가능/불가·신청처)이 맞으면 정답. 정답 칸의 부가 정보는 보너스 |
| 문서에 없음 (N01~N05) | 5 | "공고에서 확인할 수 없다"고 하고 단정하지 않으면 정답 |
| 함정 (T01~T05) | 5 | 질문의 틀린 전제(금액·나이·제외 대상 등)를 바로잡으면 정답 |

- 공고 13개에서 만들었다 (PDF·HWP·상세페이지 섞음). 정답마다 원문 근거 구절(`evidence`)이 있다.
- 근거 구절이 A1·A2 청크 양쪽에 실제로 들어 있는지 스크립트로 검사했다 (못 찾음 0건).
- '문서에 없음' 5개는 해당 공고와 코퍼스 전체에서 관련 단어를 검색해 정말 없는지 확인했다.
- 정답은 사람이 원문과 대조해 30개 모두 확정했다.
- 수정 1건: A10 "언제까지 신청해야 해?"가 신청기간과 월별 지원금 신청 기한 두 가지로 읽혀서, "이번 달 배달 실적에 대한 지원금은…"으로 바꿨다. 수정 후 다시 실행했다.

## 2. 결과 (검색 top-5, 답변 gpt-4o-mini, 채점 gpt-4.1-mini)

| 지표 | A1 고정 길이 | A2 조항 단위 |
|---|---|---|
| hit@1 | 32% | 32% |
| hit@3 | 64% | 60% |
| hit@5 | 84% | 84% |
| MRR | 0.493 | 0.501 |
| 답변 정확도 (LLM 채점) | 56.7% | 61.7% |
| 답변 정확도 (사람 채점) | - | 63.3% |
| 인용 정확도 (인용한 청크에 정답 근거가 있음) | 12/14 (86%) | 14/15 (93%) |
| 지어낸 인용 (검색 결과에 없는 id) | 0건 | 0건 |
| 문서에 없음 → "확인 불가" | 4/5 | 4/5 |
| 과잉 거절 (답이 있는데 "확인 불가") | 11/25 (44%) | 10/25 (40%) |
| 과잉 거절 중 검색 실패 | 4건 | 4건 |

hit@k 판정: 정답 근거 구절이 검색된 청크 안에 들어 있으면 hit (공백 무시). 그래서 청킹 전략이 달라도 같은 정답표로 채점한다.

검색은 두 전략이 거의 같고, A2가 답변·인용에서 조금 앞선다. 가장 큰 문제는 과잉 거절이다. A2 기준 10건 중 6건은 정답 청크가 top-5 안에 있었는데도 "확인할 수 없습니다"라고 답했다 (예: T02는 1순위 청크에 "만 15세 이상 ~ 만 34세 이하"가 있었음). 함정 5문항도 모두 "확인 불가"로 답해 틀린 전제를 바로잡지 못했다.

## 3. LLM 채점 vs 사람 채점 (A2, 30문항)

사람은 LLM 판정을 보지 않고 채점했다 (`human_grading.csv`에는 LLM 판정 칸이 없음).

| 지표 | 값 |
|---|---|
| 3단계 판정 일치율 | 19/30 (63%) |
| 정답 여부 일치율 (정답 vs 나머지) | 24/30 (80%) |
| 카파 계수 | 0.44 (보통 수준 일치) |
| 답변 정확도: 사람 / LLM | 63.3% / 61.7% |

| 사람 \ LLM | 정답 | 부분정답 | 오답 |
|---|---|---|---|
| 정답 | 13 | 6 | 0 |
| 부분정답 | 0 | 0 | 0 |
| 오답 | 0 | 5 | 6 |

총점은 비슷하지만 판정이 갈린 11문항은 방향이 반대라서 서로 상쇄됐다.

- **LLM이 더 엄격 (6문항: A08, A12, A14, A18, A19, N01):** 정답 칸의 부가 정보(데이터홈쇼핑 금액, 지원 항목, 문의처 등)가 빠졌다고 부분정답을 줬다. 사람은 질문의 핵심이 맞으면 정답으로 봤다.
- **LLM이 더 후함 (5문항: T01~T05):** 답이 공고에 있는데 "확인 불가"라고 한 함정 답변을 LLM은 부분정답으로 줬다. 사람은 사용자가 틀린 전제를 그대로 믿게 되므로 오답으로 봤다.

→ LLM 채점기를 그대로 쓰면 함정 문항 점수가 부풀려지고, 답 있음 문항 점수는 깎인다. 6단계에서 채점 프롬프트에 정답을 "핵심"과 "보너스"로 나눠 주고, 함정 문항에서 근거가 있는데 거절하면 오답이라는 기준을 넣은 뒤 다시 일치율을 잰다.

## 4. 다음 단계로 넘기는 것

- 5단계 오답노트: 과잉 거절(근거 있음 6, 검색 실패 4), 모르는데 답함(N03), 평가셋 결함(A10), 정제 누락(PDF로 인쇄한 K-Startup 상세페이지의 웹 메뉴 문구), 채점기 편향.
- 6단계 첫 실험: 답변 프롬프트를 "근거 문장을 먼저 인용한 뒤 답"하게 바꿔 과잉 거절 줄이기.
